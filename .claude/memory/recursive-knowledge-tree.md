# 递归知识树：自适应深度拆分策略

## 核心理念

用少量种子关键词，通过递归拆分维度，把一个行业的知识挖透。
不是固定层数，而是**搜索结果质量驱动深度**。

## 停止拆分的判断标准

| 搜索结果质量 | 判断 | 动作 |
|---|---|---|
| 5+ 条高质量各不相同的結果 | ✅ 粒度刚好 | 停，直接建知识 |
| 2-3 条，内容泛泛 | ⚠️ 太宽 | 继续拆成子维度 |
| 0-1 条，几乎没内容 | ❌ 太窄 | 回退到上一层 |

## 甜蜜点：2-3 层

```
Level 0: 新疆旅游（根）
  Level 1: 北疆自然风光（搜了太宽 → 拆）
    Level 2: 喀纳斯湖（搜了刚好 → 停 ✅）
    Level 2: 赛里木湖（搜了刚好 → 停 ✅）
  Level 1: 独库公路（搜了刚好 → 停 ✅，不用拆）
  Level 1: 新疆美食（搜了太宽 → 拆）
    Level 2: 烤羊肉串（搜了刚好 → 停 ✅）
    Level 2: 手抓饭（搜了刚好 → 停 ✅）
```

## 自适应深度机制

用 `infoDensity` 字段驱动决策：
- `high` → 内容丰富，不拆
- `medium` → 看情况
- `low` → 必须拆

## 实际效果

- 少量种子关键词（如"新疆旅游"）→ 拆出 6-8 个维度 → 每个维度再拆 → 叶子节点精准搜索
- 一棵知识树可以覆盖几百上千条知识
- 大主题用"先骨架后填充"策略，先建 Level 1 再逐步深入

## 与现有系统的关系

- [[geo-knowledge-keyword-synergy]] — 关键词与维度互相增强的基础方案（已实现）
- 递归拆分是在此基础上的进化：从"一层维度"变成"自适应深度的知识树"
- 关键词蒸馏提供种子关键词 → 递归拆分提供搜索词 → 搜索建库

## 待实现

当前系统只做一层维度拆分。递归拆分需要：
1. 评估步骤增加"是否需要继续拆分"的判断
2. Pipeline 支持循环/递归执行（拆分 → 搜索 → 评估深度 → 继续/停止）
3. 前端展示知识树结构（非扁平列表）
4. 进度追踪变化：不是线性 7 步，而是树状进度
